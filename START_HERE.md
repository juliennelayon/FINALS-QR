# ScanIn — updated project

Your `.env` and `.env.example` are included unchanged from the uploaded ScanIn.zip. No environment values or live database settings were changed during this work.

## Use this version

1. Extract into a **new folder**. Open the inner `ScanIn` folder containing `package.json`. This avoids keeping removed old routes/components from a previous copy.
2. Install the updated dependencies:

```bash
npm ci
```

3. If your existing ScanIn tables/functions are already installed, open Supabase SQL Editor and run **`Supabase/event_code_form_update.sql`**. This focused function update stores the exact code displayed in the Create Event form, enforces uniqueness, and prevents changing saved codes. It does not replace credentials or create/delete tables. No live SQL has been run for you.

If this is a completely new database, follow the original base-schema/full-migration order in `SETUP.md` instead.

4. Check and launch:

```bash
npm run typecheck
npm test
npx expo start --clear
```

A recent Node.js release compatible with Expo SDK 54 is required (Node 20.19+ recommended). All project-owned source/test scripts are TypeScript. Dependencies and generated bundles are installed/generated by the tools, rather than shipped as source.

## Where the actual screen code is

- `app/(tabs)/index.tsx`: Student/Teacher Home.
- `app/(tabs)/events.tsx`: student event list and state.
- `app/(tabs)/teacher.tsx`: teacher event management screen.
- `app/(tabs)/history.tsx`: Student gallery History and Teacher attendance screen.
- `app/(tabs)/scan.tsx`: camera/manual attendance flow.
- `app/(tabs)/profile.tsx`: Student/Teacher profile and student details form.
- `app/admin/`: full Home, Users, Events, Attendance, Profile, Tools, Reports, Logs and Settings implementations.
- `app/login.tsx`, `register.tsx`, `forgot-password.tsx`, `reset-password.tsx`: full authentication screens.
- `app/requests.tsx`, `notifications.tsx`: full supporting screens.
- `components/Kit.tsx`, `BackButton.tsx`: reusable UI and Back handling.
- `components/DateTimeField.tsx` / `.web.tsx`: native/web combined date-time pickers.
- `components/EventViews.tsx`: reusable event cards, details, QR display and event form.
- `lib/types.ts`: account, event, attendance, request and API/data models.

The screen files contain actual screen logic and JSX instead of one-line re-exports. Reusable forms/widgets remain shared so both teacher and admin follow the same rules.

## Navigation

Student: Home / Events / Scan / History / Profile.

Teacher: Home / My Events / Attendance / Profile.

Admin: Home / Users / Events / Attendance / Profile. Open **Admin Tools** from Profile for Reports, Requests, Activity Logs and Settings.

Back buttons are present on supporting pages and profiles. On a selected event's Attendance view, Back first returns to the event overview. Modal details/forms use their existing Close button. Main Home does not return to Login through Back.

## Before a native release

Type-checking and JS bundling do not replace testing the native date/time dialog, camera/torch, gallery and Android hardware Back on your phone. Native modules/launcher/splash changes may require a new development/preview build. Background push still requires the separately configured worker and mobile push credentials described in `SETUP.md`.

The package is source code, not a signed APK. Read `VERIFICATION.md` for exact validation scope.
